## 7. 过程中的三处偏差与说明

1. **Caddy 官方 apt 源不可用**：`dl.cloudsmith.io` 对生产与测试 IP 均返回 402。改用 **GitHub Release 的官方 `.deb`**（sha256 校验一致）安装，并移除坏源，保证 `apt update` 正常。**后续升级需重复同样的 `.deb` 方式**（或等 cloudsmith 恢复/换网络出口）。
2. **Docker 镜像构建卡死**：`deb.debian.org` 从生产机不可达（实测 30s 超时），`Dockerfile` 里的 `apt-get install ca-certificates` 卡住。**未改动仓库 Dockerfile**，而是用临时 Dockerfile（仅把 apt 源换成 `mirrors.aliyun.com`）单独构建并 tagged `dinngoo-admin:local`，再用 `docker compose up -d` 起容器。
   > **建议后续改进**：给 `dinngoo-admin` / `dinngoo-site` 的 Dockerfile 加 `ARG DEBIAN_MIRROR`（php-server 已有同类做法），避免下次重建又卡住。
3. **只读挂载导致一条无害日志**：admin 容器 `/app` 只读，Next 图片优化写 `.next/cache` 失败会打印 `Failed to write image to cache`，但**同一次请求仍返回 200**（已验证 `w=256` 返回 200）。若不想看到这条日志，可给 `/app/.next/cache` 挂一个可写卷。
