实施计划：在 Next.js 中构建基于 tRPC 的动态 MCP 网关
1. 目标
让用户在管理后台勾选希望暴露给 AI Agent 的 tRPC procedure，并生成一个专用 Token。

提供一个 MCP 端点（集成在 Next.js 中），根据 Token 动态提供工具列表，并转发调用到原 tRPC 服务。

保持原有权限模型不变，MCP 调用与普通 HTTP 调用共享相同的 tRPC context 和业务逻辑。

2. 技术栈（均为真实存在的库）
Next.js（App Router）— 主应用框架

tRPC v10+ — 现有后端逻辑

Zod — 输入校验（已使用）

zod-to-json-schema — 将 Zod schema 转为 JSON Schema（用于 MCP 工具定义）

@modelcontextprotocol/sdk — MCP 协议实现

jsonwebtoken 或 jose — 生成/验证 JWT Token

3. 架构概览
text
管理后台 UI (Next.js 前端)
   ↓ 调用 tRPC 接口
tRPC 后端（已有）
   ↓ 新增 procedure
保存用户工具选择 & 生成 Token

Next.js API Route: /api/mcp (MCP 端点)
   ↓ 解析 Token，动态提供工具，调用 tRPC caller
返回 MCP 响应给 Agent
4. 实施步骤
步骤 1：为 tRPC Procedure 添加元数据
在需要暴露为 MCP 工具的 procedure 上使用 .meta() 添加描述和分组信息。

ts
// server/routers/user.ts
import { publicProcedure, router } from '../trpc';
import { z } from 'zod';

export const userRouter = router({
  getById: publicProcedure
    .meta({ description: '根据 ID 获取用户信息', group: '用户管理' })
    .input(z.object({ userId: z.string() }))
    .query(async ({ input, ctx }) => {
      // 原有业务逻辑
    }),
  // ... 更多 procedure
});
要求：meta 信息必须是可 JSON 序列化的对象，可自定义字段。

步骤 2：实现 Procedure 元数据提取工具
创建一个工具模块 server/mcp/meta.ts，用于遍历 appRouter 并提取所有 procedure 的元数据。

函数签名：

ts
export function extractProceduresMeta(router: AnyRouter): Map<string, ProcedureMeta>
其中 ProcedureMeta 包含：

ts
{
  path: string;          // 例如 "user.getById"
  type: 'query' | 'mutation';
  input: z.ZodTypeAny | null;
  description?: string;
  group?: string;
}
实现要点：

递归遍历 router 的 _def.procedures 和子路由。

从 procedure 的 _def.meta 中读取描述和分组。

从 _def.inputs 中获取输入 Zod schema（可能为数组，取第一个）。

该模块可被管理后台 API 和 MCP 端点复用。

步骤 3：管理后台 API – 获取可选择的 Procedure 列表
在 tRPC 中新增一个 procedure（仅登录用户可访问）返回所有可暴露的工具信息。

ts
// server/routers/admin.ts
import { protectedProcedure, router } from '../trpc';
import { extractProceduresMeta } from '../mcp/meta';
import { appRouter } from '../root';
import { zodToJsonSchema } from 'zod-to-json-schema';

export const adminRouter = router({
  getAvailableProcedures: protectedProcedure.query(({ ctx }) => {
    const metaMap = extractProceduresMeta(appRouter);
    return Array.from(metaMap.values()).map(p => ({
      path: p.path,
      description: p.description ?? '',
      group: p.group ?? '未分组',
      inputSchema: p.input ? zodToJsonSchema(p.input) : { type: 'object' },
    }));
  }),
});
步骤 4：管理后台 API – 保存用户工具配置并生成 Token
新增一个 mutation，接收用户勾选的 procedure 路径列表，存储到数据库，并生成/返回 JWT Token。

数据库模型：McpConfig 表，字段包含 userId, tools（JSON 数组，每个元素含 procedurePath 和可选 customDescription），updatedAt。

Token 生成：使用 jsonwebtoken 或 jose，payload 仅包含 sub（userId）和 type: "mcp"，设置合理过期时间（如 30 天）。密钥保存在环境变量中。

ts
saveMcpConfig: protectedProcedure
  .input(z.object({
    tools: z.array(z.object({
      procedurePath: z.string(),
      customDescription: z.string().optional(),
    })),
  }))
  .mutation(async ({ input, ctx }) => {
    // 保存到数据库
    await db.mcpConfig.upsert({
      userId: ctx.user.id,
      tools: input.tools,
      updatedAt: new Date(),
    });
    // 生成 JWT Token
    const token = jwt.sign(
      { sub: ctx.user.id, type: 'mcp' },
      process.env.MCP_JWT_SECRET!,
      { expiresIn: '30d' }
    );
    return { token };

步骤 5：管理后台 UI – 工具选择页面
页面调用 getAvailableProcedures 获取列表，按 group 分组展示。

每个 procedure 显示路径、描述、输入 schema 预览。

步骤 6：在 Next.js 中实现 MCP 端点
在 app/api/mcp/route.ts 中实现 MCP 协议处理。由于 Next.js App Router 的 Route Handler 支持 Web Stream，可直接返回 SSE 或 Streamable HTTP 响应。

6.1 选择传输方式
推荐使用 Streamable HTTP：无状态，适合 Serverless 部署，每次请求独立处理。MCP SDK 已支持该传输。

如果自托管且需要 SSE，也可使用 SSEServerTransport，但需注意长连接限制。

6.2 核心逻辑代码骨架
ts
// app/api/mcp/route.ts
import { NextRequest, NextResponse } from 'next/server';
import { Server } from '@modelcontextprotocol/sdk/server/index.js';
import { StreamableHTTPServerTransport } from '@modelcontextprotocol/sdk/server/streamableHttp.js';
import jwt from 'jsonwebtoken';
import { createTRPCContextFromUserId } from '@/server/context';
import { appRouter } from '@/server/root';
import { createCaller } from '@/server/trpc';
import { extractProceduresMeta } from '@/server/mcp/meta';
import { getMcpConfig } from '@/server/db/mcp-config';
import { zodToJsonSchema } from 'zod-to-json-schema';

export async function POST(req: NextRequest) {
  const authHeader = req.headers.get('authorization');
  if (!authHeader?.startsWith('Bearer ')) {
    return new NextResponse('Unauthorized', { status: 401 });
  }

  const token = authHeader.split(' ')[1];
  let userId: string;
  try {
    const payload = jwt.verify(token, process.env.MCP_JWT_SECRET!) as { sub: string };
    userId = payload.sub;
  } catch {
    return new NextResponse('Invalid token', { status: 401 });
  }

  // 创建 MCP Server 实例
  const server = new Server(
    { name: 'my-app-mcp', version: '1.0.0' },
    { capabilities: { tools: {} } }
  );

  // 注册 tools/list 处理器
  server.setRequestHandler('tools/list', async () => {
    const config = await getMcpConfig(userId);
    const metaMap = extractProceduresMeta(appRouter);
    const tools = config.tools.map(t => {
      const meta = metaMap.get(t.procedurePath);
      if (!meta) return null;
      return {
        name: t.procedurePath,
        description: t.customDescription || meta.description || '',
        inputSchema: meta.input ? zodToJsonSchema(meta.input) : { type: 'object' },
      };
    }).filter(Boolean);
    return { tools };
  });

  // 注册 tools/call 处理器
  server.setRequestHandler('tools/call', async (request) => {
    const { name, arguments: args } = request.params;
    const config = await getMcpConfig(userId);
    const allowed = config.tools.some(t => t.procedurePath === name);
    if (!allowed) throw new Error(`Tool "${name}" not allowed`);

    // 构造 tRPC context（复用原有逻辑）
    const ctx = await createTRPCContextFromUserId(userId);
    const caller = createCaller(ctx);
    const result = await callProcedureByPath(caller, name, args);
    return {
      content: [{ type: 'text', text: JSON.stringify(result) }],
    };
  });

  // 使用 Streamable HTTP transport
  const transport = new StreamableHTTPServerTransport({
    sessionId: req.headers.get('x-session-id') || undefined,
  });
  await server.connect(transport);
  const response = await transport.handleRequest(req);
  return response;
}
辅助函数：

createTRPCContextFromUserId(userId: string)：根据用户 ID 从数据库加载用户信息、角色等，返回与正常 HTTP 请求相同的 context 对象。可在 server/context.ts 中实现并复用。

callProcedureByPath(caller, path, args)：拆分路径并调用。

getMcpConfig(userId)：从数据库获取该用户的工具配置。

步骤 7：权限与安全加固
Token 验证：使用强密钥，并考虑添加黑名单或版本号以支持撤销。

工具权限二次校验：在 tools/call 中再次检查该用户是否真的选择了该工具，防止越权。

Context 复用：确保 createTRPCContextFromUserId 与正常请求的 context 完全一致，所有原有的 RBAC 和数据过滤逻辑自动生效。

限流：可在 Route Handler 中加入基于用户 ID 的简单限流（例如每分钟 60 次）。

HTTPS：生产环境必须使用 HTTPS。

步骤 8：部署注意事项
Serverless 环境（Vercel 等）：

使用 Streamable HTTP（每次请求独立）以避免长连接超时。

函数执行时间限制内完成响应，避免长时间运行。

自托管（Node.js 容器）：

可自由使用 SSE，但 Streamable HTTP 也足够。

数据库访问：确保 MCP 端点能访问到与主应用相同的数据库（通常通过同一连接池）。
