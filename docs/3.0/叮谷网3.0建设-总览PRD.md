## 1. 背景与目标

### 1.1 背景

- 现有三端：`dinngoo-admin`（Next.js 16 + tRPC + AntD，管理后台新架构，RBAC 与业务功能从 0 迁移）、`dinngoo-site`（Next.js 16 + shadcn，C 端：酒店/机票/订单/控房/个人中心）、`php-server`（ThinkPHP 5.0 老后端，承载订单、房型、酒店、控房、付款、余额、附加产品等核心业务）。
- 2.0 已完成越南目的地、意向单预订、附加产品、订单关联、双邮箱、导出、价格标签等；3 期本期做「**架构升级 + 业务补齐**」；Agent 数字员工协作平台后置为未来规划。

### 1.2 3.0 目标（摘要）

1. **UI 重构**：管理后台与 C 端各重构一版响应式界面。
2. **RBAC 迁移**：从 0 完成 RBAC 迁移，梳理功能结构（隐藏冗余、收敛权限）。
3. **业务补齐**：房型日历价/套餐房价（含 C 端套餐列表与卖价计算）、库存（待定）、付款钉钉通知、余额修复、取消申请、收款提醒、Dashboard 优化；并将 php-server 存量核心业务迁到新 Admin。
4. **（未来）Agent 数字员工协作平台**：tRPC 元数据 / MCP 网关 / 工具集合页 / Skill / 数字员工编排 / 审计 / 钉钉协作。本期不做，见 §4。

### 1.3 明确不在 3.0 范围

- C 端在线支付、独立购买附加产品（沿用 2.0 结论）。
- 老 ThinkPHP 后端整体下线（3 期做「新功能落新架构 + RBAC 与核心业务页迁新 Admin」，存量数据全量迁移另立专项）。
- **Agent 数字员工协作平台（AG1~AG7）**列入未来规划，不计入本期。

> **性质分类说明**
> - **平滑迁移**：存量功能原样迁到新架构（Next.js + tRPC），业务逻辑与数据口径不变。
> - **新增**：3 期全新能力，老系统无对应功能。
> - **迁移+优化**：存量功能迁移到新架构的同时，顺带重构/修复/增强（响应式 UI、逻辑修正、新通知通道等）。
> - **梳理/其他**：前期盘点、文档、部署等非功能交付（S1）。

> **建议开发顺序**：S1 → S2/S3（并行）→ B11~B18 存量迁移与 B1~B10 增量按优先级穿插；S4 与业务功能解耦可并行。
> **说明**：业务功能（B 系列）逐步落到新架构，老后端仅做最小改动。Agent 平台（AG1~AG7）见 §4 未来规划，本期不排期。

## 4. 未来规划 — Agent 数字员工协作平台

> 工作量见报价表第四节。
>
> 定位：让 AI Agent（数字员工）通过标准化 MCP 接口调用叮谷网业务能力，辅助出纳/运营/客服完成日常任务，并把高频能力沉淀为「Skill」复用。模型推理由外部 AI 客户端完成，本平台负责「**能力接入 → 工具授权 → 编排 → 审计**」。届时或已有成熟系统，可直接试用或授权接入。

### 4.1 分层架构

```text
外部 AI 客户端（Claude / IDE / 自研 Agent）
        │  MCP 协议（Streamable HTTP + Bearer Token）
        ▼
┌─────────────────────────────────────────┐
│  MCP 网关  /api/mcp（tools/list·tools/call）│
├─────────────────────────────────────────┤
│  Meta 提取 / Token 鉴权 / 工具二次校验 / 限流 / 审计 │
├─────────────────────────────────────────┤
│  tRPC AppRouter（业务 procedure，复用 RBAC）    │
└─────────────────────────────────────────┘
```

### 4.2 核心模块拆解

| 子模块 | 关键内容 | 说明 |
| --- | --- | --- |
| AG1 tRPC 元数据与 Meta 提取 | 为 procedure 打 `.meta({ description, group })`；`extractProceduresMeta(router)` 递归遍历 `_def.procedures` 与子路由，返回 path/type/input/description/group | 产出 `server/mcp/meta.ts`，管理端与 MCP 端点复用 |
| AG2 MCP 网关端点 | `/api/mcp`：解析 Bearer JWT → 校验 Token → 注册 `tools/list`（按用户配置动态返回工具 + `zod-to-json-schema`）→ `tools/call`（二次校验是否勾选 → 复用 `createTRPCContextFromUserId` → 调用 procedure） | 传输用 Streamable HTTP（适配 Serverless/自托管）；`createTRPCContextFromUserId` 复用原 context，RBAC 自动生效 |
| AG3 MCP 工具集合生成页面 | 后台按 group 展示可暴露 procedure；勾选 + 自定义描述 + schema 预览；保存生成 JWT（30 天）；重新生成/复制/撤销 Token | 数据表 `mcp_config(userId, tools JSON, updatedAt)` |
| AG4 Skill 发布体系 | 各功能模块提供预置 Skill（= system prompt + 工具集 + 示例）；Skill 列表/详情/启停；一键生成对应 MCP 工具集合 | 预置 Skill 示例见 4.4 |
| AG5 数字员工实例与编排 | 数字员工 = 名称 + 角色描述（prompt）+ 绑定的工具集 + 权限范围（目的地/门店）；实例 CRUD/启停/复制 | 预置数字员工示例见 4.5 |
| AG6 安全审计 | 工具级权限二次校验（tools/call 再查是否勾选）；按用户限流（如 60 次/分）；调用审计日志（谁/何时/调什么/结果） | 支持 Token 撤销/版本化 |
| AG7 数字员工钉钉协作 | 数字员工触发事件后通过钉钉机器人/群推送（出纳收款提醒、付款审核通知）；后续可扩展群内单聊指令（P2） | 与 B2/B8 复用钉钉通道 |

### 4.3 数据模型（新增表）

| 表 | 字段 | 说明 |
| --- | --- | --- |
| `mcp_config` | userId, tools(JSON), updatedAt | 用户勾选的 MCP 工具集合 |
| `mcp_token` | userId, tokenHash, createdAt, revokedAt | Token 生命周期/撤销管理 |
| `agent_skill` | id, name, description, prompt, tools(JSON), status | Skill 定义 |
| `agent_employee` | id, name, rolePrompt, skillIds/toolSet, scope(JSON), status | 数字员工实例 |
| `agent_audit_log` | id, userId, employeeId, tool, input, result, createdAt | 调用审计日志 |

### 4.4 预置 Skill（示例）

| Skill | 描述 | 依赖 procedure 组 |
| --- | --- | --- |
| 订单查询 Skill | 按订单号/客户/日期查询订单与状态 | 订单查询组 |
| 收款提醒 Skill | 筛出到期未收款订单并生成提醒文案 | 订单 + 收款进度组 |
| 控房查询 Skill | 查询酒店控房、房态、房量 | 酒店控房组 |
| 房型价格 Skill | 查询/维护日历价格、套餐房价 | 房型价格组 |
| 付款审核 Skill | 查询待审核付款单并推送出纳 | 付款管理组 |

### 4.5 预置数字员工（示例）

| 数字员工 | 角色 Prompt 方向 | 工具集 | 权限范围 |
| --- | --- | --- | --- |
| 出纳助手 | 收款核对、付款审核、到期提醒 | 收款提醒 + 付款审核 Skill | 全局（财务） |
| 运营助手 | 订单/控房/房型价格查询与答疑 | 订单查询 + 控房查询 + 房型价格 Skill | 按目的地 |
| 客服助手 | 客户订单/余额/进度查询 | 订单查询 + 客户余额 Skill | 只读 |

### 4.6 验收要点（Agent 平台）

- 用 MCP 客户端（如 Claude Desktop）配置 `https://…/api/mcp` + Token，能列出工具并成功调用已勾选 procedure。
- 尝试调用未勾选 procedure 被拒绝；Token 撤销后立即失效。
- 后台可勾选/描述/生成/撤销 Token；Skill 可启停；数字员工可配置并绑定工具集。
- 所有 MCP 调用留审计日志，可按用户/工具/时间检索。

## 5. 跨需求共识

### 5.1 架构原则

- **单一接口层**：tRPC 是本期业务接口层。MCP 网关是未来规划，届时只作为 tRPC 的一种「传输/暴露」方式，不另写业务逻辑。
- **Context 复用**（未来）：MCP 调用与普通 HTTP 调用共享同一 `ctx`，RBAC、目的地数据过滤、审计自动生效。
- **权限最小化**（未来）：MCP 工具能力 = 用户 RBAC ∩ 用户勾选工具集，双重收敛。

### 5.2 业务共识（待确认项见 §7）

- B1 隐藏≠删除：控房财务/控房管理仅前端隐藏与权限收敛，数据保留。
- B3 缺口校验：日历价格维护时校验相邻/重叠缺口并提示。
- B4 套餐房固定：后台可配置套餐→房型映射与套餐房价；C 端选套餐后锁定房型。
- B10 C 端用价：酒店详情展示该酒店房型套餐列表；预订页用日历价与套餐价计算卖价，并完成选套餐/锁房型等交互（仍不含在线支付）。
- B8 提醒增强：优先落地「订单收款时间提醒」，复用现有通知/邮件/钉钉通道。
- 存量迁新 Admin：B11~B18 覆盖 php-server 核心业务页（订单/客户/酒店/房型/航班/收付款/控房/C 端配置）；备份、文章、微信/手机审核不迁。
