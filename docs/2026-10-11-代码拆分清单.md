## 二、执行顺序

- 按**领域分组**：同一领域（order、check、hotel、room、customer、dashboard、基础设施）的文件连着改，避免反复进出同一片代码。
- 组内**风险由低到高**：纯逻辑 lib → server helper / router → 组件 → 页面。低风险先跑通范式，高风险后做且已有前序经验。
- 领域顺序：admin（order → check → hotel → room → customer → dashboard → 基础设施与独立项）→ site（order·booking → hotel）。
- 每个序号 = 一个独立计划：单独写拆分方案、单独 review、单独测试，不合并批次提交。
