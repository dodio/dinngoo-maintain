## 二、执行顺序

- 按**领域分组**：同一领域（order、check、hotel、room、customer、dashboard、基础设施）的文件连着改，避免反复进出同一片代码。
- 组内**风险由低到高**：纯逻辑 lib → server helper / router → 组件 → 页面。低风险先跑通范式，高风险后做且已有前序经验。
- 领域顺序：admin（order → check → hotel → room → customer → dashboard → 基础设施与独立项）→ site（order·booking → hotel）。
- 每个序号 = 一个独立计划：单独写拆分方案、单独 review、单独测试，不合并批次提交。

## 三、单文件重构验收模板

每个文件的重构计划都按下面清单验收：

- [ ] `npx tsc --noEmit` 通过。
- [ ] `npm test` 全绿（dinngoo-admin，vitest）。dinngoo-site 无测试基建，以 `npx tsc --noEmit` + `npm run lint` + 页面冒烟代替。
- [ ] `npm run lint` 与基线对比**不新增 error**（admin 基线 12 errors、site 基线 19 errors，均为 `react-hooks` / `react-compiler` 类，不属拆分范围）。
- [ ] `npx eslint --format json src` 中 `max-lines` 的命中数**按文件递减**，重构后的文件不再命中（有效行 ≤400）。
- [ ] diff 只含**移动与 import/export 调整**；业务逻辑、数值口径、SQL 条件、状态流转无改动。
- [ ] admin 侧有 PHP 对照的模块（order / check / hotel / roomcontrol / customer / dashboard）parity 单测全绿，口径差异先核对 PHP 源码、不当场改。
- [ ] 拆分 router 的，`trpc.<key>.<procedure>` 调用路径与 `AppRouter` 类型不变，客户端调用点零改动（`mergeRouters` 聚合）。
- [ ] 受影响页面手工冒烟：进入页面、筛选/排序/分页、打开抽屉与弹窗、提交或导出各至少一次，无 console 报错。
- [ ] 新增文件符合 AGENTS.md：单一职责、就近原则、无 `export *`、无碎片化文件（<60 行的叶子优先合并）。
