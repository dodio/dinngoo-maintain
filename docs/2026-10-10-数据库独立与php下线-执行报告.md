# 执行报告：数据库独立部署 + PHP 下线 + throne 域名移除（测试环境）

- **执行日期**：2026-10-10
- **执行环境**：测试机 `ht2026090513191`（206.119.178.88，Ubuntu 24.04 + Docker + 宿主机 Caddy）
- **范围**：仅测试环境执行；生产迁移步骤见 [迁移-生产环境-数据库独立与php下线.md](../deploy/迁移-生产环境-数据库独立与php下线.md)
- **原拓扑**：`php-server` 一个 compose 栈（mysql + php-fpm + nginx）承载后台与数据库，两个 Next 应用共用它的 MySQL 与上传目录
- **新拓扑**：独立 `dinngoo-db`（MySQL）+ `dinngoo-site`（C 端）+ `dinngoo-admin`（新后台，占 `op.dinngoo.xyz`）

## 1. 做了什么

1. **MySQL 独立**：新建 `/srv/dinngoo-room/mysql/`（compose + `.env` + `init/` + `migrations/` + `seed/`），项目名 `dinngoo-db`，服务名仍为 `mysql`，数据卷改为独立外部卷 `dinngoo-db_mysql_data`。
2. **数据搬迁**：停旧栈后把 `php-server_mysql_data` 整卷 `cp -a` 到新卷；**旧卷保留未动**，作为回滚快照。
3. **上传目录中性化**：`php-server/public/upload` → `/srv/dinngoo-room/data/upload`，容器内挂载点 `/dinggu-php-upload` → `/dinggu-upload`（admin 读写、C 端只读）。
4. **PHP 下线**：`php-server` 栈 `docker compose down`（不带 `-v`），目录归档到 `/srv/dinngoo-room/_archive/php-server-20261010`。
5. **邮件接管**：把 PHP 的 18 个 SMTP / MAIL 键迁入 `dinngoo-admin/.env.production.local`。
6. **域名收敛**：Caddy 删除 `throne.dinngoo.xyz` 站点块；`op` 保持指向新后台 `127.0.0.1:13010`。
7. **运维脚本适配**：启动脚本、备份路径、容器日志列表、口令同步脚本、Caddy 模板与相关文档全部更新。

## 2. 切换顺序（实际执行）

1. 全量 `mysqldump` + 配置备份
2. 记录基线（表数 / 行数 / 附件数）
3. `php-server` 栈 `down`（保留卷）
4. 复制数据卷 `php-server_mysql_data` → `dinngoo-db_mysql_data`
5. 建 `/srv/dinngoo-room/mysql/`（compose、`.env`、init、migrations、seed）
6. 复制附件到 `/srv/dinngoo-room/data/upload`
7. 两个应用仓库改 compose 挂载 → 提交 push → 服务器 `git pull`
8. 启动 `dinngoo-db`，校验数据 → 两个应用 `up -d next` 重建
9. 写入邮件 env → 重建新后台
10. Caddy 去掉 throne → `reload`
11. 跑备份 / 日报 / 指标 / 容器日志扫描验证
12. 归档 `php-server`

1. `docker compose -f /srv/dinngoo-room/mysql/docker-compose.prod.yml down`（不带 `-v`，新卷保留）。
